# 界面与操作系统 · 0.3.0

全屏战场以棋盘、实体备战区和棋子为中心。手机横屏采用中央棋盘、顶部赛况、左侧羁绊/伤害统计、右侧排名和底部经济操作的战场 HUD。准备阶段的五卡商店以可收起的半透明横幅覆盖棋盘中上部，战斗阶段自动释放棋盘。模型沿用程序生成低多边形方向，商店缩略图和场上棋子来自相同模型工厂。

HUD 初始化组件节点一次；根据快照修改文字、图片、类和显隐。玩家/队伍名称使用 textContent。装备槽按需创建并复用。商店 PNG 在第一次需要时渲染并缓存，临时缩略图 renderer 随后释放；不逐帧重新生成卡面。

商店概率条直接投影 `RULES.shopOdds`。战斗伤害榜只在客户端从确定性回放的 `damage` 事件重建，按当前观战阵营过滤并显示前六名；切换战场、回放跳转或同步恢复不会向权威状态写入统计数据。

## 输入与权威边界

状态包括 idle、selected、dragging、equipment、swapping、pending。显式的 pointerdown / move / up 驱动操作，不再用一个含义不清的 `onPick(pick, drag)` 混合点击和拖放。

- 超过 7 CSS px 移动进入拖拽；430 ms 长按查看详情。触摸拾取扩大邻近棋子的命中范围，并以落点高亮辅助确认。
- 拖动时锁住相机，暂时收起招募栏；使用指针落点显示预览，原位轮廓仍在。松手先取得目标再恢复 HUD/取景，避免缩放后改变实际提交格。
- 拖动自己的非公共棋子时，底部操作栏切换为独立出售区，与棋盘上的公共格纵向分层。拖入并松手只打开出售确认弹层；确认后才提交带原棋子版本的 `sell`，取消、Escape、阶段或版本变化均不出售。详情浮层中的出售按钮保持直接提交。
- 放回原格不发指令。无效落点只显示简短原因，模型返回权威位置。
- 点击其他棋子只改变选择。拖拽到占格，或显式「换位」后点击目标，才请求 swap。
- 成功动作等待权威 receipts。金币、位置、星级、装备均来自下一份快照，预览不修改领域状态；拒绝回执在最近操作附近提示。
- Pointer Cancel、丢失捕获、右键、Escape、窗口失焦、隐藏、尺寸变化、观战切换与阶段变化清理手势。源棋子版本变化、被合成或转交也取消；无关快照更新不取消合法拖动。
- 商品和棋子使用业务对象锁防止同一操作重复提交。超过 8 秒仍无回执时显示等待房主提示，并以原 commandId 重发等待中的交易；房主优先返回已保存的结果。不能把超时当成失败并擅自回滚金币。

原子换位命令示例：

```json
{
  "type": "swap",
  "commandId": "session:12",
  "round": 4,
  "unitId": "unit-7",
  "unitVersion": 2,
  "targetId": "unit-9",
  "targetVersion": 5
}
```

## 布局与表现

相机根据顶部对阵、底部资源栏和两侧 HUD 的可用区域取景，投影边界包含整个棋盘、双方实体备战格、公共区与棋子高度。中央商店是可收起遮罩，不永久压缩取景。844×390 手机横屏是主布局基准；桌面保持相同区域关系并限制 HUD 最大宽度。竖屏等比压缩信息密度，窄屏的羁绊与排名以按钮展开，列表自身可滚动，页面不整体滚动。主要按钮与列表行保持至少 44 CSS px 的交互高度。

装备托盘和棋子详情是临时浮层，可关闭。点装备可阅读效果，再点自己的棋子穿戴；所有关键操作均不依赖 hover。布局考虑系统安全区，顶部右侧留给 Parti 胶囊。实际平台胶囊尺寸与各设备视口仍须人工验证。

战斗事件驱动朝向、起手/释放/命中/后摇、受击闪光、伤害/治疗数字、范围预警、弹道和粒子。回放帧携带持续状态和在途动作，跳播或重连可重建表现。62 枚棋子的普攻与技能表现 ID、时序及色板来自 content；建筑、虫族、熊猫和格斗家具有独立程序化轮廓。渲染层不复制规则半径。数字最多同时 48 个，技能预警最多 24 个，瞬时特效最多 96 个；关闭实时阴影，DPR 上限 1.5，离开时释放资源。
